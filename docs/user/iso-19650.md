# ISO 19650 / MIDP / TIDP

S9 module — ISO 19650 Master / Task Information Delivery Plans
plus filename validation against the standard's structural rules.

## Filename validation

`Core/Iso19650Codes.cs` + `Iso19650FilenameValidator` enforce the
ISO 19650 document naming convention:

`{ProjectCode}-{Originator}-{Volume}-{Level}-{Type}-{Role}-{Number}`

with reference data for Type codes, Role codes, and Suitability
codes (S0–S6 + D1–D5). Invalid filenames at document create
return 400 with the failing field. Reference data was
reconciled against ISO 19650-2:2018 in T-S9-02.

## MIDP — Master Information Delivery Plan

Per-project `MidpEntry` rows: container reference, deliverable
title, format, due date, responsible party, current status
(Planned / In Progress / Submitted / Accepted / Rejected). The
MIDP is the project-level master schedule of what every
information container will deliver.

## TIDP — Task Information Delivery Plan

Per-task / per-team `TidpEntry` rows that decompose the MIDP into
team-level commitments. Each TIDP entry references its parent
MIDP entry plus the team performing the work.

## Common gotchas

- **The Type / Role enums are CIMS internal** — the strings stored
  match the ISO 19650 codebook but the enum surface can be
  cross-referenced via `Iso19650Codes.cs`.
- **Per-tenant Type / Role overrides** are a reasonable v1.1
  ask but currently not in the backlog; raise if pilot needs.
- **Suitability transitions** integrate with the CDE state machine
  (S0–S6 are work-in-progress / shared / published bands;
  D1–D5 are deliverable bands).
