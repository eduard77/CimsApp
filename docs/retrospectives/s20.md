## Retrospective

### What went well

- **Triple Option A held cleanly.** Daily diary uniqueness
  (per-user-per-day), NCR workflow (5-state linear), photo
  attachment (defer to v1.1). 10-for-10 across S10 → S20.
- **The state-machine pattern is now muscle memory.**
  `Core/NcrWorkflow.cs` is the 8th state machine in CIMS;
  the shape (`Transitions` dict + `TransitionRoles` dict +
  three pure-function helpers) takes minutes to write because
  every prior workflow has the same skeleton. NcrWorkflow
  unit tests are also from the same template; 3 cases pin
  the contract.
- **Audit-twin pattern extended naturally to two more
  entities.** `dailydiary.created`, `dailydiary.updated`,
  `ncr.created`, `ncr.assigned`, `ncr.transitioned` — five
  new structured event names, all atomic with the underlying
  entity write via the PR #33 audit-twin contract.
- **DateOnly avoided a timezone tarpit.** Daily diary's
  `DiaryDate` is `DateOnly` — service-layer accepts UTC
  date only. Avoids the "is this 11:59 PM yesterday or
  12:01 AM today?" rabbit hole. The S20 kickoff Top-3 risk #2
  named this; mitigation was upfront.

### What did not go well

- **Heavy sprint pushed timing limits.** 18h estimate (heaviest
  since S18). The session-end pressure meant the NCR assignee
  selection UI got deferred (B-123) — the API works but the
  page only shows transition buttons, not an assign-to picker.
  Honest gap; will land as a v1.1 polish.
- **Local test verification still WDAC-blocked.** Fourth sprint
  in a row (S17 was the only sprint without new tests to
  verify). CI is the verification gate.
- **No live verification before commit.** Same concern as S19;
  the new pages were built statically against the established
  pattern but not poked at 375px width or verified that the
  date picker renders correctly. Carries forward.

### What surprised me

- **The /ncrs page action column is ugly with multiple
  buttons.** Each row potentially shows 1-2 transition buttons
  in the Action column; on mobile the responsive table drops
  the column anyway, but on desktop the buttons stack
  awkwardly when both Cancel and Forward are valid. Acceptable
  for v1.0 pilot; v1.1 polish candidate.
- **Sequential per-project NCR numbering is the Nth
  re-implementation of this pattern.** RFI, change request,
  inspection, gateway package, NCR — each has its own
  "compute next number from the highest existing" helper.
  Promotable to a shared utility at v1.1; would require a
  careful refactor across all entities. Tracked here as a
  passing thought, not a v1.1 backlog entry yet (the cost
  isn't pressing).
- **The session ran longer than expected.** Started ~3 retros
  ago suggesting the C-11 day; that recommendation has now
  been carried forward 5 retros. The "we can still code for
  2 hours" budget that opened S19 + S20 is fully consumed.
