## Retrospective

### What went well

- **Triple Option A held cleanly through to close.** Evidence
  shape (discriminated link), Auditor role (project-scoped
  invitation), Export format (ZIP). 8-for-8 across S10 / S11 /
  S12 / S14 / S15 / S16 / S17 / S18. The "ask once with a
  concrete proposal" pattern is now empirically the established
  shape for sprint kickoffs.
- **The role-hierarchy gap was a clean privilege guard.**
  `UserRole.ExternalAuditor` is intentionally outside
  `RoleHierarchy` in `Core.cs`. `Array.IndexOf(RoleHierarchy,
  ExternalAuditor)` returns -1, so `HasMinimumRole(ExternalAuditor,
  anything)` returns false. Every existing mutation gate that
  uses the helper auto-rejects without per-call special-casing.
  Found at design time when checking the existing
  `HasMinimumRole` semantics — adding the new role at the end
  of the enum and out of the array gave correct behaviour by
  construction. Generalisable: when adding a new role to a
  privilege-tiered enum, the default for "what can it do" should
  be "nothing" until explicitly placed in the hierarchy.
- **Reuse over rewrite, again.** AuditorAdminService.RevokeAsync
  delegates to `AuthService.RevokeUserTokensAsync` for the cutoff
  bump + refresh sweep. The auditor revocation thus gets the
  same audit-twin event chain (`auth.user_admin_revoke`) as
  every other revocation, plus an `auditor.revoked` event for
  the assignment-specific record. Two events for one action,
  but each is the right grain.
- **Exactly-one-FK validation as a service-layer concern, not a
  DB constraint.** The `EvidenceArtefact` table allows zero or
  more nullable FKs at the schema level; the service layer
  enforces "exactly one OR bare-description". This trades a
  hard schema guard for flexibility on bare-description
  evidence (no entity FK, just a Description) — and gives a
  single place to put the validation message. Tests cover the
  edge cases (zero / multi / cross-project).

### What did not go well

- **Razor UI pages deferred.** The kickoff task table lumped UI
  into T-S18-05 (4h) — that scope was optimistic given the
  three pages' shapes (Evidence list + add dialog, Auditor
  assignment list + create + revoke, Export download button on
  the existing Audit page). Rather than rush an underweighted
  UI surface or push the sprint past single-session, deferred
  to a fast-follower commit. Same precedent as S1 T-S1-03 CBS
  CSV import (API-only at sprint close, UI follow-up). Honest
  but a real gap if "sprint complete" is read strictly.
- **Local test verification still blocked.** Third sprint in a
  row where the laptop's WDAC policy blocks `dotnet test`
  discovery on the rebuilt assembly. The pattern is now firmly
  established as a permanent constraint of this dev environment;
  CI is the verification gate. No new ground to cover.
- **The CIControllerBase change to `GetProjectRoleAsync` is not
  unit-tested.** The fall-through to AuditorProjectAssignment
  is only exercised via integration / smoke. Could extract the
  resolution logic to a static helper for direct unit testing;
  deferred because the current behaviour is small (5 lines)
  and the auditor scenarios are easier to verify end-to-end
  via PowerShell smoke walk anyway.

### What surprised me

- **The audit-twin pattern (PR #33) extends naturally to evidence
  rows.** `evidence.added` and `evidence.removed` are just two
  more action names in a long list of structured events. The
  AuditService write happens in the same SaveChanges as the
  EvidenceArtefact insert/delete; atomicity is automatic.
  Generalisable: any new entity that wants discoverability via
  audit gets it for free with one line in the service layer.
- **ZIP-as-bundle is meaningfully simpler than PDF.** No
  rendering library dependency, no per-section layout work, no
  Ch 24.6 24-hour wait. The bundle is plain JSON files, which
  external auditors can inspect with any text editor / diff
  tool. PDF is prettier but ZIP is more honest.
- **The `EvidenceArtefact` discriminated-link shape is maybe
  too clever.** It works (one of four nullable FKs), but the
  alternative — a polymorphic `SourceType` + `SourceId` (Guid)
  pair — would be smaller and more extensible. Deferred to v1.1
  / B-NNN if a fifth source type ever needs adding.

### What I will try differently next sprint

- **Estimate UI scope separately** from service / test scope.
  Lumping them at kickoff hides the deferral risk. Future
  sprint task tables should split T-X-04 (services) from T-X-04a
  (UI) so the deferral is explicit if it happens.
- **Extract testable controller-base helpers when adding
  cross-cutting role logic.** The `GetProjectRoleAsync`
  ExternalAuditor fall-through is a behaviour change that
  belongs in a unit-tested static method. Refactor as a
  fast-follower (or in S19 if another piece of role-resolution
  logic lands there).
- **Promote B-NNN evidence polymorphic-FK to v1.1 backlog
  proactively** if a fifth source type comes up. Right now
  the four-FK shape is fine; adding a fifth would tip it.
