## Decisions required at kickoff

Three triple-decision Option A defaults — pattern carried from
S10..S19 (9-for-9 so far).

### Decision 1 — Daily Diary uniqueness shape

- **Option A (default, lean):** **Per-project per-day per-user
  composite key** (allow multiple authors to log for the same
  day; e.g. site supervisor + safety officer + foreman). Soft
  uniqueness via `(ProjectId, DiaryDate, AuthorId)` index;
  duplicates rejected at service layer with a clear error.
- Option B: One row per project per day (single canonical entry).
  Simpler but loses the multi-author signal real construction
  sites have.
- **Choice: Option A.**

### Decision 2 — NCR workflow states

- **Option A (default, lean):** **5-state linear:** `Raised →
  Assigned → InProgress → Resolved → Closed`. Plus
  `Cancelled` from `Raised`/`Assigned` only. State machine in
  `Core/NcrWorkflow.cs` matching the prior workflow patterns
  (Cde, Variation, ChangeRequest, Gateway, Compensation, Pdca,
  Inspection).
- Option B: Richer workflow with re-open, escalation, root-cause
  analysis steps. Per-tenant configurable workflow → v1.1 / B-NNN.
- **Choice: Option A.**

### Decision 3 — Photo attachment for NCRs

- **Option A (default, lean):** **Defer photo upload to v1.1.**
  v1.0 ships NCR with a `PhotoStorageKey` string field that
  callers can populate with an external blob reference (e.g.
  Azure Blob URL); the actual upload UX is v1.1 / B-120 alongside
  any other multimedia attachment work.
- Option B: Ship inline upload to `wwwroot/storage/ncr/{id}/`
  with size + MIME validation.
- **Choice: Option A.** B-120 unblock condition: pilot field
  team requests photo capture as a v1.0 ship blocker.

## Top-3 risks (CATEGORY only)

1. **NCR state-machine off-by-one transitions.** The pattern
   has bitten earlier sprints (CdeStateMachine + ChangeRequest);
   per-transition tests catch it. Mitigation: explicit
   `Core/NcrWorkflow.cs` with full state-pair coverage.
2. **Daily Diary date timezone.** Storing `DiaryDate` as a
   `DateOnly` avoids timezone confusion vs DateTime; service
   layer expects UTC for everything else, so UI converts to
   project-local at render. Mitigation: use `DateOnly` for the
   date field and keep timezone concerns at the UI layer.
3. **Estimate overrun.** 18h is the heaviest sprint since S18.
   If implementation runs over a single session the sprint ships
   what's done + carries the rest as a fast-follower (S18
   precedent).
