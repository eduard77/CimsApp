## Decisions required at kickoff

Three triple-decision Option A defaults — pattern carried from
S10 / S11 / S12 / S14 / S15 / S16 / S17 / S18 (8-for-8 so far).

### Decision 1 — Pen test commissioning approach

- **Option A (default, lean):** **Spec-and-defer.** Agent drafts
  `docs/security/pen-test-scope-2026-05-05.md` capturing the
  target endpoint surface, threat model, scope-in / scope-out
  boundaries, severity rubric, and acceptance bar (zero open
  criticals to ship v1.0). User commissions an external tester
  using the spec; the actual pen test runs out-of-sprint; the
  sprint close lists "external pen test" as a carry-forward
  obligation that closes when the report is received.
- Option B: Agent drives an internal "pen test substitute"
  (OWASP review + automated scanners like OWASP ZAP). Less rigour;
  doesn't satisfy PAFM's "tester signed off" semantics.
- **Choice:** **Option A.** External pen test is a signature
  step; can't be substituted by internal review. B-112 unblock
  condition: "v1.0 ship blocked AND no external pen tester
  available within the schedule" — would make the substitute
  acceptable if formally waived.

### Decision 2 — Load test rig

- **Option A (default, lean):** **k6 script committed at
  `scripts/load-test/k6-100-vu.js`.** k6 is OSS, scriptable in
  JavaScript, free, runs anywhere. Script exercises the
  v1.0-critical paths (login, project create, RFI list, audit
  query) at 100 virtual users for 5 minutes. Pass criteria
  documented inline: p95 latency < 1s, error rate < 0.1%.
  User runs the script against a deployed instance when the
  rig is ready; the sprint close lists "execute load test" as
  a carry-forward obligation.
- Option B: Cloud load testing service (Azure Load Test, k6
  cloud, etc.). Adds a paid dependency.
- **Choice:** **Option A.** B-113 unblock condition: "first
  pilot deployment where local k6 from a developer machine is
  insufficient to simulate realistic geographic-distribution
  load".

### Decision 3 — Secrets management for production

- **Option A (default, lean):** **Environment variables +
  ASP.NET configuration provider chain.** Production reads from
  env vars; dev reads from `appsettings.Development.json` (not
  committed). Per-developer local override via
  `dotnet user-secrets`. ADR-0015 captures the decision +
  rotation expectations + the v1.1 migration path to Azure Key
  Vault. Production deployment doc enumerates the required env
  vars.
- Option B: Azure Key Vault (or AWS Secrets Manager). Adds a
  cloud dependency, auth flow (managed identity), and
  per-deployment Key Vault provisioning.
- **Choice:** **Option A.** B-114 unblock condition: "first
  production deployment that needs cross-region failover OR
  pilot exits internal-only mode (multi-tenant SaaS rollout)".

## Top-3 risks (CATEGORY only — S9-retro pattern)

1. **OWASP review surfaces a real shipping bug.** The post-S1
   smoke walk era found four latent production bugs (PR #41-#44);
   a methodical OWASP walkthrough has the same potential. Risk
   is positive (the agent FINDS bugs) — mitigation is to fix
   forward inside this sprint where the fix is small (one-attribute
   change; small refactor) and surface as B-NNN where larger.
2. **Pen test spec underestimates the target surface.** The API
   has ~80 endpoints across 18 sprints' worth of services. Easy
   to miss a class of endpoint in the scope. Mitigation: enumerate
   the endpoint surface from `Controllers.cs` + every per-domain
   `*Controllers.cs` file; cross-reference with role-matrix doc.
3. **k6 script doesn't exercise the actual hot paths.** v1.0
   pilot use cases include "operator runs morning project review"
   (audit + actions + RFI list) and "PM creates payment cert"
   (cost domain). Script could pessimise toward easy paths.
   Mitigation: include both read-heavy and write-heavy scenarios;
   document the assumed baseline operator workflow.
