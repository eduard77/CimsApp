## Decisions required at kickoff

Three triple-decision Option A defaults — pattern carried from
S10..S20 (10-for-10 so far).

### Decision 1 — User-doc structure

- **Option A (default, lean):** **One markdown file per module
  area** under `docs/user/`, organised by sidebar nav grouping
  (e.g. `cde.md`, `rfis.md`, `actions.md`, `cost.md`, `risk.md`,
  `evidence.md`, `diary.md`, `ncrs.md`, etc.). Each file
  covers: what the page is for, who uses it, primary actions,
  common gotchas, links to relevant ADRs / PAFM appendices.
  Plus an `index.md` table of contents.
- Option B: One large user manual (single PDF or single markdown).
  Worse for searchability; worse for incremental updates as
  modules evolve.
- **Choice: Option A.**

### Decision 2 — Admin doc shape

- **Option A (default, lean):** **`docs/admin/` with three
  files:** `setup.md` (env vars, prerequisites, first-run),
  `operations.md` (day-2 ops — backups, log inspection, user
  admin), `troubleshooting.md` (common errors + remediation).
  Cross-references the relevant ADRs (esp. ADR-0016 secrets
  management).
- Option B: Single all-in-one admin manual.
- **Choice: Option A.**

### Decision 3 — Training walkthrough format

- **Option A (default, lean):** **Walkthrough scripts in
  `docs/training/` capturing end-to-end "day in the life"
  scenarios for three primary roles** (SuperAdmin / OrgAdmin,
  Project Manager, Site User). Markdown + numbered steps +
  expected screenshots / observations. Video production is
  external-execution (user-action: record screencasts following
  the scripts).
- Option B: Inline screencast recording. Requires recording
  toolchain + post-production; out-of-scope for the agent.
- **Choice: Option A.** B-124 unblock condition: pilot operator
  reports walkthrough scripts as insufficient without video.

## Top-3 risks

1. **Docs drift from code.** Worst failure mode for a docs
   sprint — write a doc that's accurate today, code changes
   tomorrow, doc rots. Mitigation: cross-reference ADRs +
   per-sprint retros (which DO get updated alongside code);
   keep user-facing docs at the "what + why" level rather than
   "exact button labels."
2. **Scope underestimation.** ~14 module areas at "do it well"
   pace easily blows past 5h. Mitigation: tight per-doc
   target (200-400 words; bullet-shape; no marketing prose).
3. **Swagger surface incomplete.** v1.0 has ~80 endpoints;
   if Swagger UI doesn't render some, that's a real
   v1.0-ship-gate finding worth fix-forward time. Mitigation:
   verify the Swagger UI loads and lists every controller's
   actions; fix any that fail.
